# Task brief template

Copy this file and replace the bracketed prompts with the smallest useful description of one real task. Keep unknown facts marked UNKNOWN; do not turn a proposal, example, or old quote into a current promise.

## 1. Task summary

- **Task name:** [short name]
- **Requester / team:** [name or role; do not include private identifiers in a public copy]
- **Date prepared:** [YYYY-MM-DD]
- **Desired outcome:** [what decision, artifact, or result should this task produce?]
- **Why it matters:** [the problem this outcome addresses]

## 2. Inputs

- **Source material:** [files, links, fields, or observations]
- **Format and size:** [file types, row count, language, limits]
- **Required fields:** [what must be present]
- **Allowed assumptions:** [what may be inferred, if anything]
- **Missing or uncertain inputs:** [list them; use UNKNOWN where appropriate]
- **Data handling:** [redaction, retention, deletion, or return requirements]

Do not paste credentials, API keys, private keys, customer files, or unnecessary personal data into a public issue or discussion. Share sensitive inputs only through a currently verified, authorized private route.

## 3. Expected output

- **Uncertainty labels:** [for example VERIFIED, NEEDS_CHECK, NOT_FOUND]
- **Delivery location:** [where the result should appear; verify this entry is current]

The deadline is a request, not a delivery guarantee. Confirm the Provider's current availability and stated time window for this exact task.

## 6. Budget and commercial terms

- **Budget:** [amount or UNKNOWN]
- **Currency:** [currency or UNKNOWN]
- **Pricing unit:** [per task, hour, item, result, subscription, or UNKNOWN]
- **Quote required:** [yes / no / UNKNOWN]
- **Payment route:** [verified route or UNKNOWN]
- **Refund / cancellation terms:** [verified terms or UNKNOWN]

Do not treat a purchase button, old example, or generic price as a current quote. Confirm the Provider, unit, payment method, and any account/API/wallet requirements before paying.

## 7. Acceptance test

The task passes only when each applicable check has evidence:

- [ ] The requested scope was executed or the incomplete part is explicitly listed.
- [ ] The output contains the required fields and format.
- [ ] Sources and observed dates are present where required.
- [ ] Unknown, missing, or conflicting values are labeled instead of guessed.
- [ ] The delivery location is accessible to the intended recipient.
- [ ] A named requester confirms the result is useful for the stated purpose.
- [ ] Corrections, follow-up, and support route are known.

**Acceptance owner:** [role]
**Correction window or route:** [details or UNKNOWN]

## 8. Data authorization

- **Authorized data owner:** [role]
- **Permitted data:** [minimum necessary categories]
- **Permitted destination:** [specific Provider / service entry]
- **Retention and deletion:** [verified policy or UNKNOWN]
- **Prohibited data:** credentials, API keys, private keys, payment secrets, unnecessary personal data, and customer files not required for this task.

No data should be transmitted until the destination, authorization, and handling conditions are verified.

## 9. Explicit exclusions

- [ ] No fake order, fake customer, fake demand, or test payment.
- [ ] No wallet connection or transaction signing unless separately authorized and genuinely required.
- [ ] No paid API call unless the current price, purpose, and authorization are confirmed.
- [ ] No claim that automation, delivery, payment, or a result is available without current evidence.
- [ ] No work outside the Included section without an approved change.
